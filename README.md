# Учёт рабочего времени по камерам FaceID

Веб-платформа: администратор загружает Excel-выгрузку из системы камер FaceID, платформа считает по каждому сотруднику приход, уход, отработанное время и опоздания за месяц.

- **Сайт:** React + TypeScript, публикуется на GitHub Pages (бесплатно).
- **База и вход:** Supabase (бесплатный тариф).
- **Роли:** `admin` — загрузка файлов, настройки, удаление; `viewer` — только просмотр. Публичной регистрации нет.

---

## Правила расчёта

| Что | Как считается |
|---|---|
| Пришёл | Первая отметка сотрудника за день на любой камере |
| Ушёл | Последняя отметка за день |
| Отработано | Ушёл − Пришёл (обед вычитается, только если включён в настройках) |
| Опоздание | Пришёл − начало рабочего дня (по умолчанию 08:00). Секунды не считаются |
| Повторные отметки | Отметки одного человека в пределах 60 секунд — одна отметка |
| Одна отметка за день | Уход неизвестен: отработано 0, опоздание **не** начисляется, день помечен жёлтым |
| Выходные и праздники | Время учитывается, опоздание — нет |
| Отделы без графика | По умолчанию уборщицы (`Agency\Cleaner`): опоздание не считается |
| Ночные отметки 00:00–04:00 | Не учитываются |
| Сотрудник | Определяется по ID из FaceID, не по ФИО |

Начало дня, обед, рабочие дни, праздники и отделы без графика меняются в разделе **«Настройки графика»** и сразу применяются ко всем месяцам.

## Установка (один раз, ~30 минут)

### 1. Supabase

1. Зарегистрируйтесь на [supabase.com](https://supabase.com) **на почту, которую вы реально читаете**: туда придёт предупреждение, если база начнёт засыпать.
2. **New project.** Регион — ближайший к Таджикистану (например, Frankfurt). Сохраните пароль базы.
3. **SQL Editor → New query** → вставьте содержимое `supabase/migrations/001_init.sql` → **Run**.
4. **Отключите регистрацию:** Authentication → Sign In / Providers → выключите *Allow new users to sign up*. Даже если её забыть выключить, посторонний ничего не увидит (доступ выдаётся только через таблицу `profiles`), но лучше выключить.
5. **Создайте пользователей:** Authentication → Users → *Add user → Create new user* (email + пароль, включите *Auto Confirm User*).
6. **Выдайте роли:** откройте `supabase/manage_users.sql`, подставьте email и имя, выполните в SQL Editor.
7. **Ключи:** Project Settings → API (или API Keys). Нужны *Project URL* и *anon / publishable key*.
   ⚠️ Ключ `service_role` / `secret` **никогда** не вставляйте в сайт и в GitHub.

### 2. Проверка на своём компьютере

```bash
npm ci
cp .env.example .env.local      # и впишите URL и ключ
npm run dev                     # откроется http://localhost:5173
npm run demo                    # то же, но без базы, с данными в памяти
npm test                        # все тесты
```

### 3. Публикация на GitHub Pages

1. Создайте репозиторий на GitHub и загрузите туда проект (`git push`). Excel-файлы в репозиторий не попадут — они в `.gitignore`.
2. **Settings → Secrets and variables → Actions → New repository secret:**
   - `VITE_SUPABASE_URL` — Project URL
   - `VITE_SUPABASE_ANON_KEY` — anon / publishable key
3. **Settings → Pages → Source: GitHub Actions.**
4. **Actions → Deploy → Run workflow** (или любой push в `main`). Через 1–2 минуты сайт будет по адресу `https://<логин>.github.io/<репозиторий>/`.
5. Если тесты не прошли или Secrets не заданы, публикация остановится, и старая версия сайта останется рабочей.

### 4. Чтобы база не засыпала (обязательно)

Бесплатный проект Supabase ставится на паузу после 7 дней без запросов.

1. **Основной способ — [cron-job.org](https://cron-job.org)** (бесплатно): создайте задание раз в 3 дня:
   - URL: `https://<ваш-проект>.supabase.co/rest/v1/health?select=ok`
   - Headers: `apikey: <anon key>` и `Authorization: Bearer <anon key>`
2. **Запасной:** workflow `Keep Supabase awake` в этом репозитории запускается сам раз в 3 дня. GitHub отключает его, если в репозитории 60 дней не было коммитов, поэтому он только запасной.
3. Если база всё же уснула: Supabase → проект → **Resume project**. Данные сохраняются.

## Как пользоваться

1. **Загрузка файла** (админ): перетащите выгрузку FaceID → проверьте период и количество сотрудников → «Загрузить в базу». Данные за даты из файла заменятся, остальные месяцы не тронутся. Если загрузка прервётся, в базе ничего не изменится.
2. **Табель:** месяц, поиск, фильтр по отделу, «С опозданиями», «Без отметки ухода», сортировка. Клик по сотруднику открывает его дни.
3. **Скачать Excel:** итоги и детализация по дням за месяц (или по одному сотруднику).
4. **История загрузок** (админ): кто и когда загружал, удаление ошибочно загруженного месяца.

**Храните исходные файлы FaceID.** На бесплатном тарифе Supabase нет резервных копий; если данные потеряются, их можно восстановить, загрузив файлы заново.

## Что платформа не может (ограничения данных)

- Если человек прошёл мимо камер, его приход будет записан позже реального.
- Отгулы, командировки и больничные в выгрузке FaceID не отмечены.
- Дубли сотрудников и незаполненные отделы исправляются только в самой системе FaceID.

## Структура проекта

```
src/core/          расчёт: разбор Excel, приход/уход, опоздания, итоги (без UI, покрыт тестами)
src/lib/           подключение к Supabase, демо-режим, экспорт в Excel
src/pages/         страницы: табель, сотрудник, загрузка, история, настройки, вход
supabase/          SQL: таблицы, права доступа, функции загрузки; выдача ролей
test/              тесты расчёта, тесты базы и прав доступа (настоящий Postgres в памяти)
.github/workflows/ публикация на Pages, пинг базы
```

Тест на реальной выгрузке запускается, если положить файл в `fixtures/real.xlsx` (папка не попадает в git).
