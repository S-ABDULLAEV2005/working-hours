# Учёт рабочего времени по камерам FaceID (Davomot)

Администратор загружает Excel-выгрузку системы камер FaceID — платформа считает по каждому сотруднику приход, уход, отработанное время, опоздания, переработку и отгулы.

- **Сайт:** React + TypeScript, публикуется на GitHub Pages (бесплатно).
- **База, вход, файлы:** Supabase (бесплатный тариф).
- **Языки:** таджикский, русский, английский (переключатель в правом верхнем углу).

## Роли

| Роль | Что видит и делает |
|---|---|
| **Администратор** | всё: загрузка файлов, история, настройки графика и праздников, пользователи, исключение сотрудников |
| **Рохбар** (руководитель) | обзор дня, табель, страницы сотрудников, проверка отгулов |
| **Только просмотр** | обзор дня, табель, отгулы — без изменений |
| **Коргар** (сотрудник) | только «Моя страница»: свои дни, график, опоздания; отмечает свои отгулы |

Публичной регистрации нет: аккаунты создаёт администратор на странице «Пользователи». Сотрудники входят **по ID из FaceID** и паролю.

## Правила расчёта

| Что | Как считается |
|---|---|
| Пришёл / ушёл | Первая / последняя отметка за день на любой камере |
| Отработано | Ушёл − пришёл (обед — только если включён в настройках) |
| Опоздание | Пришёл − начало дня (по умолчанию 08:00). Секунды не считаются |
| Отгул | Если сотрудник отпросился с начала дня (например, 08:00–12:00), опоздание считается от конца отгула. Отклонённый руководителем отгул не учитывается |
| Переработка | Работа после конца дня (17:00 или время сокращённого дня); в выходные и праздники — всё время |
| Повторные отметки | Отметки одного человека в пределах 60 секунд — одна отметка |
| Одна отметка за день | Уход неизвестен: отработано 0, опоздание не начисляется |
| Выходные и праздники | Опоздания нет, время идёт в переработку |
| Отделы без графика | По умолчанию уборщицы: опоздание и переработка не считаются |
| «Мало посещений» | Был меньше 25% рабочих дней загруженного периода → отдельная вкладка, не входит в итоги |
| Исключённые | Администратор вручную исключает гостей и дубли; вернуть можно в любой момент |
| Ночные отметки 00:00–04:00 | Не учитываются |

Всё, кроме постоянных правил, меняется в «Настройках графика» и сразу пересчитывает все месяцы.

## Установка с нуля (~40 минут)

### 1. Supabase

1. Зарегистрируйтесь на [supabase.com](https://supabase.com) на почту, которую реально читаете.
2. **New project**, регион — Central EU (Frankfurt).
3. **SQL Editor → New query** → вставьте `supabase/migrations/001_init.sql` → **Run**.
4. Затем так же выполните `supabase/migrations/002_roles_absences.sql`.
5. Authentication → Sign In / Providers → выключите *Allow new users to sign up*.
6. Создайте себя: Authentication → Users → *Add user* (email, пароль, ✓ *Auto Confirm User*), затем выполните первый блок `supabase/manage_users.sql` с вашим email — вы администратор.
7. Установите функцию пользователей (раздел ниже).
8. Ключи: кнопка **Connect** или Project Settings → **API Keys** → *Publishable key* (или *Legacy* → `anon`). URL — Project Settings → **Data API**. ⚠️ `secret` / `service_role` никуда не вставлять.

### 2. Функция управления пользователями

1. Supabase → **Edge Functions** → **Deploy a new function** → **Via Editor**.
2. Имя: **`admin-users`** (латиницей, английская раскладка, без пробелов).
3. Удалите пример, вставьте весь `supabase/functions/admin-users/index.ts` → **Deploy function**.
4. Функция → **Details** → выключите **Verify JWT** → **Save** (проверка входа и роли сделана в самом коде).
5. ✅ На сайте под администратором раздел «Пользователи» показывает список.

При изменении файла функции повторите шаг 3 (вставить новый код → Deploy).

### 3. Проверка на компьютере

```bash
npm ci
cp .env.example .env.local      # впишите URL и ключ
npm run dev                     # http://localhost:5173
npm run demo                    # без базы, данные в памяти
npm test                        # все тесты
```

### 4. GitHub

Для бесплатного GitHub Pages репозиторий **публичный**: код увидят все. В нём нет данных и секретов — `.gitignore` исключает `.xlsx`, `fixtures/`, `.env.local`. Проверяйте перед коммитом:

```powershell
git add .
git status
git ls-files --cached | Select-String -Pattern "xlsx|xls|csv|env.local|fixtures"   # должно быть пусто
git commit -m "..."
git push
```

### 5. Публикация на GitHub Pages

1. Settings → Secrets and variables → Actions: `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`.
2. Settings → Pages → Source: **GitHub Actions**.
3. Дальше каждый `git push` публикует сайт сам (Actions → зелёная галочка). Если тесты не прошли — сайт не обновится, старая версия продолжит работать.

### 6. Чтобы база не засыпала (обязательно)

Бесплатный проект Supabase засыпает после 7 дней без запросов.

- **cron-job.org** раз в день: URL `https://<проект>.supabase.co/rest/v1/health?select=ok`, заголовок `apikey: <publishable/anon key>` (только он).
- Запасной: workflow `Keep Supabase awake` (те же Secrets).
- Если уснула: Supabase → проект → **Resume project**.

### 7. Письма для восстановления пароля (по желанию)

Без своей почты Supabase отправляет письма только участникам вашего проекта Supabase и не больше 2 в час. Чтобы «Забыли пароль?» работало для администраторов:

1. Создайте отдельный ящик, например Gmail `davomot.platform@gmail.com`; включите в нём двухфакторную защиту.
2. Google-аккаунт → Безопасность → **Пароли приложений** → создайте пароль для «Supabase».
3. Supabase → Authentication → **Emails / SMTP Settings** → *Enable custom SMTP*: host `smtp.gmail.com`, port `465`, user — адрес ящика, password — пароль приложения, sender — тот же адрес. Сохраните.
4. Authentication → **URL Configuration** → *Site URL* и *Redirect URLs*: адрес вашего сайта (`https://<логин>.github.io/<репозиторий>/`).
5. ✅ На странице входа: «Забыли пароль?» → ваш email → письмо приходит → ссылка открывает сайт с окном «Задайте новый пароль».

Без этой настройки всё равно работает основной путь: забывшему пароль новый выдаёт **второй администратор** («Пользователи» → «Новый пароль»). Поэтому администраторов должно быть минимум двое.

## Обновление существующей установки (версия 2)

Если платформа уже работает (выполнен только `001_init.sql`):

1. **SQL Editor** → выполните `supabase/migrations/002_roles_absences.sql` → `Success`.
2. **Edge Functions → admin-users** → вставьте новый `supabase/functions/admin-users/index.ts` → **Deploy**. Проверьте, что Verify JWT остался выключенным.
3. Замените файлы проекта (кроме `.env.local`) → `git add .` → проверка → `git commit` → `git push`.
4. ✅ Проверка: Storage → bucket `absence-files` есть и он **Private**; «Настройки графика» показывают праздники списком; на «Пользователях» доступны 4 роли и кнопка «Аккаунты для сотрудников».

> Если когда-нибудь повторно выполните `001_init.sql`, сразу после него выполните `002_roles_absences.sql` ещё раз — иначе права ролей вернутся к старым.

## Как пользоваться

**Администратор**
1. «Загрузка файла» — выгрузка FaceID за день, неделю или месяц. Платформа предупредит о совпадениях ID/ФИО. Данные за даты файла заменяются, остальные не трогаются.
2. «Пользователи» → «Аккаунты для сотрудников» — создаёт логины (ID из FaceID) и пароли всем выбранным, затем **сразу** скачайте Excel с паролями и раздайте их лично. Это самый чувствительный документ — после раздачи удалите.
3. «Настройки графика» — начало/конец дня, обед, рабочие дни, праздники и сокращённые дни, порог «мало посещений», отделы без графика.
4. На странице сотрудника — «Исключить из табеля» (гости, дубли).

**Рохбар**
- «Обзор дня» — последний загруженный день (или любой по календарю): на работе, вовремя, опоздали, нет на работе, в отгуле; нажмите число — откроется список. Справа — переработка за месяц.
- «Отгулы» — новые отгулы с подтверждениями: «Проверено» или «Отклонить» с причиной.

**Коргар (сотрудник)**
- «Моя страница» — цифры за месяц (нажатие на цифру фильтрует дни), график прихода, список дней.
- «Отметить отгул» — дата, время, куда и зачем, фото подписанного руководителем письма. Отгул засчитывается сразу; руководитель может его отклонить.

**Храните исходные файлы FaceID**: на бесплатном тарифе нет резервных копий.

## Ограничения данных

- Если человек прошёл мимо камер, приход запишется позже реального.
- Дубли сотрудников и пустые отделы исправляются только в самой системе FaceID.
- Таджикский перевод интерфейса — черновой; таблица для проверки: `Переводы_для_проверки.xlsx`, правки вносятся в `src/i18n/dict.ts`.
